# Fine-Tuning Dataset Infrastructure

This directory holds the instruction-tuning data for **DeadlockTutorLLM**.

## Schema Specification
Each instruction sample follows the standard Alpaca/JSONL format:

```json
{
  "instruction": "Explain whether an unsafe state in operating systems guarantees that a deadlock will occur.",
  "input": "",
  "output": "No. An unsafe state does not necessarily mean that the system is currently deadlocked or that a deadlock is inevitable. An unsafe state merely implies that the operating system cannot guarantee that all processes will finish without deadlock if every process simultaneously requests its maximum declared resources. If processes complete without requesting their maximum claims, the system can still avoid deadlock."
}
```

## Planned Dataset Composition (Target: 1,000–3,000 examples)
1. **Concept Explanations**: Deep dives into Coffman conditions, preemption, avoidance vs. prevention.
2. **Worked Banker's Problems**: Explaining deterministic traces generated by the solver.
3. **Deadlock Detection**: Interpreting wait-for cycles and multi-instance reduction.
4. **Misconception Corrections**: Disentangling unsafe state vs. deadlock, starvation vs. deadlock.
5. **Hint-First Tutoring**: Pedagogical prompts that guide students rather than immediately giving answers.
6. **MCQ & Viva Questions**: University examination style questions with answer rationales.
7. **Lab & Concurrency Exercises**: POSIX threads, mutex locks, and dining philosophers.

> **Note**: Synthetic or bulk examples must NOT be generated until validation tools and verification protocols are established in Phase 7.
